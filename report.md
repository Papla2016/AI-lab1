## 1. Цель работы

Реализовать воспроизводимый grounded RAG-конвейер от пользовательских документов до структурированного ответа с проверяемыми цитатами.

## 2. Архитектура RAG

`documents → loader → recursive chunks → embeddings → Chroma → dense/BM25+RRF → reranker → context → LLM → Pydantic validation`.

## 4. Chunking

Использован рекурсивный splitter, размер 1000 и overlap 150 символов (указать фактические настройки). Малый chunk способен разорвать определение и потерять смысловые связи. Чрезмерно большой объединяет нерелевантные темы, ухудшает точность поиска и увеличивает prompt. Overlap сохраняет связь на границах.

## 7. Hybrid dense + BM25

BM25 помогает точным терминам, dense — семантическим перефразировкам. Reciprocal Rank Fusion объединяет ранги без некорректного сравнения разных шкал.

## 9. Zero-shot vs few-shot vs CoT-structured

Zero-shot использует только grounded-инструкции; few-shot добавляет примеры найденного, отсутствующего и многоисточникового ответа; `cot_structured` предварительно выбирает chunk IDs без раскрытия длинной цепочки рассуждений. Сравнить соблюдение схемы и grounded-поведение: _заполнить_.

## 10. Structured Output

`RAGAnswer` содержит answer, citations, confidence, insufficient_context. Pydantic проверяет JSON, а код сверяет `(source, chunk_id)` с context и делает не более одного retry.

## 11. Agentic routing

Консервативный router различает `DOCUMENT_QUESTION` и `GENERAL_OR_OUT_OF_SCOPE`; это классификация маршрута, а не автономный агент.
