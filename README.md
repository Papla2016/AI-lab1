# Лабораторная работа № 1: воспроизводимый RAG

Проект реализует реальный локальный конвейер: PDF/Markdown/TXT → рекурсивный chunking → SentenceTransformers → персистентный Chroma → dense или BM25+dense/RRF retrieval → необязательный cross-encoder → защищённый prompt → OpenAI-compatible LLM → проверенный Pydantic JSON с цитатами. Код не привязан к ALT Linux.

## Быстрый старт (Python 3.11+)

```bash
python -m venv .venv
source .venv/bin/activate                 # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
```

По умолчанию используется лёгкая multilingual E5-модель. При первом запуске она загружается из Hugging Face. Для полностью офлайн-запуска заранее поместите модель в кэш или задайте `EMBEDDING_MODEL` как путь к локальной модели.

Настройте в `.env` любой OpenAI-compatible сервер. Пример для локального Ollama:

```bash
ollama pull qwen2.5:7b
ollama serve
# значения из .env.example уже указывают на http://localhost:11434/v1
```

Ключи никогда не коммитятся: `.env` исключён из Git. Файл `.env` необязателен — безопасные локальные defaults применяются из `src/config.py`.

## Веб-интерфейс и многошаговый чат

Нужны Python 3.11+ и локальная [Ollama](https://ollama.com/download). GPU, Docker и платный API не требуются. Для CPU рекомендуется начать с `qwen2.5:3b`; `qwen2.5:7b` требует больше памяти и времени. Установите зависимости в виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate
# CPU-сборка уменьшает размер установки на машине без GPU:
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

В отдельном терминале запустите сервер (если Ollama уже запущена как служба, второй сервер не нужен):

```bash
ollama serve
```

Загрузите выбранную модель и запустите интерфейс:

```bash
ollama pull qwen2.5:3b
streamlit run app.py
```

Откройте адрес, который Streamlit напечатает в терминале. В боковой панели укажите `qwen2.5:3b`; по умолчанию имя модели берётся из `.env`. Для постоянной настройки:

```dotenv
LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=qwen2.5:3b
```

`LLM_API_KEY=ollama` — служебное значение для локального сервера. Для другого OpenAI-compatible сервера сохраните его URL, ключ и модель в `.env`; интерфейс и диагностика не выводят конфигурацию с ключами. При недоступном сервере интерфейс показывает сообщение и сохраняет возможность продолжить работу. На CPU первый ответ может быть медленным; клиент ограничивает ожидание 120 секундами и не делает скрытых повторов сетевых запросов.

Во вкладке **«Чат»** можно вводить любые вопросы, например «Напиши Python-функцию сортировки», и продолжать диалог. История хранится в `st.session_state` текущей браузерной сессии и очищается кнопкой «Очистить историю». Это не постоянное хранилище диалогов.

| Режим | Поведение |
| --- | --- |
| RAG — по документам | Использует существующий `RAGPipeline`, показывает реальные цитаты, источники и confidence. При недостатке контекста сообщает об этом и не переключается на обычный чат. |
| Обычный чат | Отправляет историю диалога напрямую в Ollama, отвечает свободным текстом без обязательного JSON и без загрузки embedding-модели. |
| Автоматический | Существующий LLM-router выбирает RAG или обычный чат; выбранный режим отображается рядом с ответом. |

Предыдущие сообщения не используются как документальные доказательства в RAG. Явный режим RAG выполняет поиск без предварительного отказа router; автоматический режим классифицирует вопрос один раз. CLI `ask` сохраняет прежнюю классификацию перед поиском.

В боковой панели доступны `dense`/`hybrid`, `zero_shot`/`few_shot`/`cot_structured`, `top_k` (число кандидатов поиска) и reranking. Финальное число фрагментов ограничивает `FINAL_K` из `.env`. По умолчанию reranking выключен; при первом включении потребуется скачать cross-encoder. Embeddings и reranking выполняются на CPU.

В поле **«Дополнительные пожелания к ответу»** можно менять инструкции, например «Отвечай кратко, приводи примеры на Python». Они применяются к обычному чату и RAG; кнопка сброса возвращает исходные инструкции. В RAG эти пожелания подчиняются требованиям grounding, JSON и проверки цитат. Файлы в `prompts/` не перезаписываются. Подробная диагностика раскрывает найденные фрагменты, страницы, scores, chunk IDs, контекст, промпт, router и время запроса.

Во вкладке **«Документы»** загрузите PDF, TXT или Markdown, нажмите «Сохранить файлы», затем «Переиндексировать документы». Файлы сохраняются в `data/`; существующие имена не перезаписываются. Индексация использует тот же loader, chunking и Chroma, что CLI. Результат показывает количество файлов/чанков и ошибки чтения. Переиндексация заменяет коллекцию всем текущим корпусом, поэтому операция блокируется на время тестовых прогонов. Для первого запуска retrieval нужен доступ к Hugging Face либо локальная модель через `EMBEDDING_MODEL`.

## Тестирование в браузере

Вкладка **«Тестирование»** запускает существующий pytest и сценарии из `evaluation/questions.json`. Unit-тесты работают с mock LLM и не требуют Ollama. RAG evaluation выполняет реальные вызовы и требует загруженного корпуса, embedding-модели и запущенной Ollama.

Можно выбрать вопросы, retrieval и стратегии промптов; полный исходный набор — 7 × 2 × 3 = **42 сценария** для одной настройки reranking. Для сравнения с reranking и без него используются обе настройки. Пользовательские вопросы с ожидаемым наличием ответа, необязательными эталоном и источником хранятся отдельно от исходного набора.

Результаты обновляются по мере выполнения без обновления страницы: прогресс, текущий сценарий, время, статусы и раскрывающиеся подробности. Остановка сохраняет уже полученные результаты; текущий RAG-сценарий завершается перед остановкой (он может содержать несколько вызовов LLM). Одновременно допускается один прогон; запросы чата, загрузка и индексация во время него блокируются. Unit-тесты запускаются отдельным процессом pytest; веб-запросы к RAG не вызывают CLI через subprocess.

Технический успех и проверка качества показываются отдельно: валидность структуры, соответствие цитат реальному контексту, ожидаемый отказ/достаточность и ожидаемый источник. Наличие JSON и цитаты само по себе не подтверждает фактическую правильность ответа. Эталон сохраняется для проверки; если используется буквальное сравнение, оно отдельно обозначается. Диаграммы и таблицы сравнивают одинаковые вопросы по настройкам, времени и долям валидных ответов/цитат. Эти доли не являются точностью или гарантией отсутствия галлюцинаций.

У каждого запуска есть уникальный ID и timestamp. Результаты сохраняются в `evaluation/results/`, доступны просмотр предыдущих запусков и скачивание JSON, CSV, Markdown. Файлы содержат вопросы, ответы и фрагменты вашего корпуса: учитывайте это при экспорте. Исходные вопросы не перезаписываются. Сохраняется запуск из терминала:

```bash
python -m evaluation.evaluate --output evaluation/results.md
python -m pytest -q
```

Evaluation сохраняет отчёт и возвращает код `1` при технических ошибках, `130` при отмене. Несовпадение ожидаемого поведения без технической ошибки отмечается как `Failed` в отчёте и не меняет код завершения.

Общая логика чата и документов находится в `src/backend.py`, транспорт LLM — в `src/llm.py`, runner проверок — в `evaluation/runner.py`. И CLI, и Streamlit используют эти компоненты; Chroma работает локально без отдельного сервера.

## Данные и индексация

Самостоятельно положите документы `.pdf`, `.md`, `.txt` в `data/` (включая подпапки), затем:

```bash
python -m src.main index
```

PDF читается постранично; ошибки отдельного файла логируются, а остальные файлы продолжают обрабатываться. Повторная индексация атомарно с точки зрения коллекции заменяет прежний корпус, поэтому удалённые документы не остаются в выдаче. Индекс хранится в `storage/`.

Размер chunk по умолчанию — 1000 символов, overlap — 150 (`CHUNK_SIZE`, `CHUNK_OVERLAP`). Это практичный баланс: слишком малые фрагменты разрывают определения и логические связи; слишком большие смешивают темы, снижают точность retrieval и расходуют context window. Рекурсивное разбиение предпочитает абзацы, затем строки, предложения и слова. Стабильный `chunk_id` образуется из источника, страницы, позиции и текста.

## Retrieval отдельно от LLM

```bash
python -m src.main search "Как обновить пакеты?" --retrieval dense --top-k 5
python -m src.main search "Как обновить пакеты?" --retrieval hybrid --top-k 5
```

JSON выдачи содержит score, source, page, chunk_id и полный текст. Hybrid — не две независимые выдачи: rankings dense и BM25 объединяются Reciprocal Rank Fusion, устойчивым к несовместимым шкалам scores.

## Вопрос к RAG

```bash
python -m src.main ask "Чем отличается Sisyphus от стабильной ветки?" --retrieval hybrid --prompt few_shot --debug
python -m src.main ask "Как работает apt?" --retrieval dense --prompt zero_shot
python -m src.main ask "Как работает apt?" --retrieval hybrid --prompt cot_structured
```

`--debug` печатает вопрос, решение LLM-router, режим, кандидатов до/после rerank, scores, context и итоговый prompt, но не конфигурацию и не секреты. `--prompt` принимает три действительно разных режима: `zero_shot` содержит только grounded-инструкции; `few_shot` добавляет три примера; `cot_structured` выполняет отдельный краткий выбор релевантных chunk IDs (без запроса длинной цепочки рассуждений), а затем формирует ответ. Итог каждого режима всё равно проверяется одной схемой `RAGAnswer`. Reranking включается `RERANK_ENABLED=true`; тогда top-N кандидатов оценивает локальный cross-encoder и оставляет `FINAL_K` с неизменёнными metadata.

Пример формы ответа (конкретные значения появятся только из вашего корпуса):

```json
{
  "answer": "Команда описана в руководстве.",
  "citations": [{"source": "guide.md", "chunk_id": "8f12ab34cd56ef78"}],
  "confidence": "high",
  "insufficient_context": false
}
```

Citation допускается только для реально переданного chunk. Достаточный ответ обязан иметь хотя бы одну citation, а недостаточный — иметь пустой список. Неверная комбинация, схема или выдуманная citation вызывает один исправляющий retry, затем явную ошибку. Пустой/слабый retrieval (`MIN_DENSE_SCORE`) возвращает детерминированный `insufficient_context=true`. Перед retrieval небольшой structured LLM-router отделяет вопросы по документам от беседы и явно посторонних тем; при `GENERAL_OR_OUT_OF_SCOPE` поиск не выполняется.

## Evaluation и anti-hallucination

После индексации и запуска LLM выполните:

```bash
python -m evaluation.evaluate --output evaluation/results.md
pytest -q
```

Скрипт прогоняет 7 вопросов через dense/hybrid и zero-shot/few-shot/cot-structured, сохраняя sources, chunk IDs и ответы. Для последнего, намеренно постороннего вопроса он сначала получает реальный no-RAG ответ той же LLM, а затем сравнивает его с grounded RAG. Ничего не предзаписано: перенесите фактические наблюдения в `report.md`. Отдельный запуск baseline доступен как `python -m src.main baseline "Какова температура поверхности Венеры?"`; он не делает retrieval и не передаёт CONTEXT. Инструкции внутри документов изолированы delimiters CONTEXT и system prompt требует считать их данными, что защищает от простой prompt injection (но не является абсолютной sandbox-защитой).

## Диагностика

* `python -m src.main --help` — все команды.
* Пустая `data/` даёт понятную ошибку и не стирает существующий индекс.
* Пустой индекс даёт пустой search/недостаточный контекст.
* Ошибка соединения при `ask` означает, что OpenAI-compatible сервер не запущен или `.env` неверен.
* Настройки моделей, порогов, top-N и final-k документированы в `.env.example`.
